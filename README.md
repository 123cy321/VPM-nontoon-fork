## 安装

**① 一键**：打开 **[添加页面](https://catandling.github.io/VPM-nontoon-fork/)** → 点按钮 → VCC 会弹「添加仓库」确认框。

> 为什么 README 里不直接放 `vcc://` 按钮：GitHub 会把这种自定义协议的链接过滤掉（只剩文字）。
> 要手动触发，把下面这行粘到浏览器地址栏即可：

```text
vcc://vpm/addRepo?url=https://catandling.github.io/VPM-nontoon-fork/vpm.json
```

**② ALCOM / VCC 手动添加**：找到「添加仓库 / Add Repository」，粘贴 **listing 地址**（`vpm.json`，不是 zip）：

```text
https://catandling.github.io/VPM-nontoon-fork/vpm.json
```

装完在包列表里会看到两个包：

| 包 | 要不要装 | 是什么 |
|---|---|---|
| **`NonToon (Fork)`** | **必装** | 着色器本体 |
| **`NonToon (Fork) Tools`** | 建议装 | lilToon 材质转换器 + 三类光源工具 + 自阴影烘焙（纯可选，不影响着色器） |

> 装工具包会自动带着色器；只装着色器不会带工具包（依赖是单向的）。

## 五分钟上手

### 1. 界面语言

**0.3.7 起不用管**：中文会自动生效。（中文 Windows 上 ShaderCore 的默认语言是 `zh-CN`，旧版本包只带了
`zh-Hans.po`，两者对不上，所以默认状态下 165 条属性里只有 35 条是中文；现在会自动补齐，117 条。）

### 2. 手上有 lilToon 材质？一键迁过来

菜单 **`Tools ▸ lilToon → NonToon 转换器`**，或右键 Hierarchy 里的模型 / Project 里的材质。

- **生成新材质，绝不动你原来的 lilToon 材质**
- 报告会逐条写清楚：哪些是 1:1 搬过去的、哪些是近似、哪些没支持
- 1:1 的包括：光照上下限 / 单色 / 无光照、1、2、3 层阴影色与边界模糊、**逐像素阴影遮罩**、发光全套
- MatCap、边缘光、距离淡出、毛发、描边这些是**近似**，转完看一眼再微调

### 3. 地图太黑 / 地图的光不对？给 avatar 加「自带光」

工具包提供**三类**东西，先想清楚要哪一种（下一节详解）：

| | **① Avatar 光源** | **② 自有光源** | **③ 亮度自适应（插件）** |
|---|---|---|---|
| 一句话 | 真挂一盏 Unity 灯 | 着色器里加一路私有光 | 诊断 + 亮度预设 + 游戏内径向 |
| 要动材质吗 | 不用（任何着色器都吃） | 要 | 它帮你写 |
| 阴影 | 实时（跟姿势变） | 烘焙（固定姿态） | 用 ② 的 |
| 代价 | 占 VRChat `Lights` 计数 → 最高 Poor | 几乎为零 | 无额外代价 |

## 光源组件详解

### 先搞清一件事：VRChat 里**挂在 avatar 上的脚本不会运行**

VRChat 官方文档 [Allowed Avatar Components](https://creators.vrchat.com/avatars/whitelisted-avatar-components/whitelisted-avatar-components/) 明确写着：

> "Any component on the following list can be used in VRChat.
> **Other components or custom scripts won't work in VRChat and may stop you from uploading your avatar.**"

白名单里只有 `Animator` / `Animation` / `Light` / `Renderer` / `VRCAvatarDescriptor` / PhysBone 这一类，
**没有自定义脚本**。

这件事决定了本包所有光源工具的设计：

| 你看到的东西 | 它真正的身份 | 进 VRChat 后 |
|---|---|---|
| `NTAvatarLight`（①） | 编辑器期的**设置载体** | 组件本身不运行；但**它创建的那盏 `Light` 会照常工作**（`Light` 在白名单里） |
| `NTSelfLight`（②） | 编辑器期的**设置载体**（把参数与烘焙结果写进材质） | 组件本身不运行；**材质里的参数与阴影贴图照常工作** |
| ③ 插件生成的 Animator 参数 / 动画剪辑 / 径向菜单 | 全部在白名单内 | **正常工作**（这也是"游戏内可调"唯一可行的做法） |

所以：
- 上传时如果 SDK 提示「有不允许的组件」，**移除这些组件不影响效果**（③ 插件面板里有「上传前清理」按钮）
- 想"在游戏里调亮度"，只能走 **Animator + 动画剪辑 + Expression 参数**（见 ③）

---

### ① Avatar 光源（不用改材质）

菜单：`GameObject ▸ NonToon ▸ ① 创建 Avatar 光源（不用改材质）`

它会在你指定的节点下创建一盏**真正的 Unity `Light`**：

- **与着色器无关**：lilToon / Poiyomi / NonToon / Standard 都会照到它
- **Culling Mask 默认第 10 层（PlayerLocal）** —— VRChat 里只有"本地玩家自己的 avatar"在这一层，
  所以它**不会照亮世界、也不会照亮其他玩家**
- 自动打开层级里所有 Renderer 的 `Receive Shadows`（有些 avatar 默认是关的，关了就不出影子）
- 支持色温（直接用 Unity 的 `Light.colorTemperature`，6500K ≈ 白）

参数：

| 参数 | 说明 |
|---|---|
| 光源组件 | 由创建器生成的那盏灯，一般不用手改 |
| 颜色 / 使用色温 / 色温(K) | 光色。开了色温后 `color` 变成乘算 |
| 光强 | 默认 1.5 |
| 聚光灯角度 | 越小越集中、影子越干净 |
| 照射范围（米） | 只照自己就调小，别烧到别人 |
| 阴影类型 / 浓度 / 偏移 | `Soft` 软阴影推荐；出现条纹状噪点（阴影痤疮）就把偏移调大 |
| Culling Mask | 默认 `1<<10`（PlayerLocal） |
| 渲染模式 | `ForcePixel` 阴影质量最好 |
| 光的方向来源 | 留空 = 用本节点朝向；想让 PhysBone 控制方向，就把本节点挂到被驱动的那根骨骼下 |

**代价（面板上也会写）**：
- 占 VRChat 性能等级的 `Lights` 计数。PC 上 Excellent / Good / Medium 都要求 `Lights = 0`，
  只有 Poor 允许 1 —— 也就是说**挂一盏实时光，性能等级最高只能到 Poor**
- 额外渲染一张阴影贴图，**每个看到你的人都付这份开销**
- 影子能不能看到取决于**观看者**的 Shadow Quality；Unity 的 Shadow Distance 之外没有影子
- 多人同时开这类光会互相叠加，人挤人时可能照成一片白
- **Quest 端基本不可用**

### ② 自有光源（需要在材质启用）

菜单：`GameObject ▸ NonToon ▸ ② 创建自有光源（需要在材质启用）`

原理完全不同：**在 NonToon 着色器里加一路私有光**，只有这个材质看得见。

- 别人看不到你的光、也不会照亮世界
- 阴影是**烘焙的深度图**（不是实时阴影），**永远可见，Quest 也能用**
- 代价几乎为零：默认 0 采样（强度为 0 或不开 PCSS 时）

材质面板里对应「Self Light」组，组件面板上也能调同一批参数（组件会写进材质）：

| 参数 | 说明 |
|---|---|
| 自有光源（开关） | 打开才有效；② 组件会自动帮你打开 |
| **只接受光源编号**（Light ID） | 0 = 任意。同一模型上可并存多路自带光，用编号让材质"只认哪一路"。组件写入时会自动盖章编号 |
| 颜色 / 使用色温 / 色温(K) | 1000–20000K，6500 ≈ 中性白 |
| 强度 / 方向（世界空间，指向光源） | 方向就是"光从哪来" |
| **只由它照亮** | 丢掉世界光、环境光、光照贴图、天空盒反射 → avatar 在任何地图里长得一样 |
| **屏蔽地图环境光**（0–1） | 只想压掉环境光、保留地图太阳时用（近似） |
| 匹配世界光颜色 / 方向 | 探测地图环境光的颜色与主光方向，让自己的光跟着变。**读的是着色器本来就有的数据，不额外花采样** |
| 阴影强度 / 阴影颜色 / 阴影强度遮罩 | 阴影处染什么色、逐像素控制哪里影子深 |
| **接收遮罩** | 逐像素控制哪里收影子（比如眼白不想被刘海投到，就涂黑） |
| PCSS 软阴影 + 画质四档 | 低 20 / 中 36 / 高 60 / 极高 96 次采样每像素 |
| 阴影硬化（Clamp） | 把软边压成硬边，动画风用 |
| 阴影距离 | 离相机超过设定距离自动关掉 |
| 自备阴影贴图（Map 组） | 自己提供灰度深度图 + 原点/三轴/半宽高/远近平面 |

组件上有两个按钮：

- **只同步参数（不烘焙）**：只把参数写进材质
- **烘焙自阴影并写入材质**：CPU 光线投射生成深度图后写入（PCSS 可到极高、贴图可到 2048）

> **影子是"烘焙那一刻的姿态"**：VRChat 里做不到实时自阴影（avatar 不能带相机/渲染纹理）。
> 换姿势重新烘焙即可。

### ③ 亮度自适应与防煤（编辑器插件）

菜单：**`Tools ▸ NonToon ▸ ③ 亮度自适应与防煤（编辑器插件）`**

解决的问题：**全黑地图里 avatar 变成一块煤**，而且"亮多少"每个人喜好不同，最好**能在游戏里随手调**。

#### 先说结论：防煤的主力不是"加灯"，而是**抬高亮度下限**

NonToon 与 lilToon 的亮度公式**完全一致**（[lilToon 官方文档「ライティング・明るさ設定」](https://lilxyzw.github.io/lilToon/ja_JP/base/lighting.html)）：

```
RGB = clamp(RGB, _LightMinLimit, _LightMaxLimit);   // 亮度下限 / 上限
RGB = lerp(RGB, Mono, _MonochromeLighting);         // 单色化
RGB = lerp(RGB, 1.0,  _AsUnlit);                    // Unlit 化
```

而 **NonToon 的 `_LightMinLimit` 默认是 0** ⇒ 地图没光时 clamp 出来就是纯黑，也就是"煤"。
lilToon 官方建议 VRChat 里把下限放在 **0.0~0.2**；本插件默认给 **0.35**（更保守，因为 NonToon 默认是 0）。

好处：**零采样代价**（不涉及阴影采样，也不消耗 VRChat 的 `Lights` 计数），不需要打开自有光源。

**实测数字**（全黑场景，真实 GPU 渲染；下限越高越亮，且不会白飞）：

| 亮度下限 | 画面均值 | 非黑像素 |
|---|---|---|
| **0**（NonToon 默认） | 0.0020 | **0.0%** ← 一块煤 |
| 0.15（lilToon 官方推荐区间） | 0.0719 | 17.3% |
| **0.35**（本插件默认预设） | 0.1066 | 17.3% |
| 0.6（更保守） | 0.1353 | 17.3% |
| 对照：改走自有光那条路 | 0.1684 | 17.3% |

> 这个思路与 [LightLimitChanger（LLC）](https://github.com/Azukimochi/LightLimitChangerForMA) 一致 ——
> 它的官方描述是「**シェーダーの明るさの下限/上限のアニメーションを生成するツール**」，
> 也就是"为亮度上下限生成动画"。本插件第 ⑤ 节做的事一样，只是面向 NonToon。

#### 插件做的五件事（它不会往你的 avatar 上挂任何组件）

**1. 场景光照诊断** —— 读当前场景的环境光（三种模式）、平行光数量与亮度、着色器实际使用的 SH L0，
给出 0–1 的世界亮度估算，并直接告诉你"在这种图里会不会变煤"。配一个 **「模拟全黑地图」** 按钮：
临时把主光压到 0.02、环境光压到 0.01，**让你肉眼验证**自己的 avatar 在极暗环境里是不是煤；看完点「还原」。

> 这里量的是**你当前打开的场景**。VRChat 里地图光照各不相同、脚本又不运行，
> 所以真正的保险是下面的亮度预设 + 游戏内径向。

**2. 亮度预设（主力）** —— 一键写入材质：

| 按钮 | 写入 |
|---|---|
| **防煤（下限 0.35）** | `_LightMinLimit = 0.35`、上限 1 |
| lilToon 推荐（0.15） | `_LightMinLimit = 0.15` |
| 明亮（0.5） | `_LightMinLimit = 0.5` |
| 压过曝（上限 0.85） | `_LightMaxLimit = 0.85`（地图太亮/白飞时用） |
| 还原官方默认（0 / 1） | 两个都还原 |

另外还能直接拉：**单色化**（地图灯光颜色很怪时去掉彩度）、**Unlit 化**（越接近 1 越像 Unlit、底更亮；
注意你变亮的同时，相对地周围的人会显得更暗）。

**3. 兜底：自有光源**（可选，收起在折叠区里）—— 需要"完全不受地图影响"时才用：
打开着色器里的自有光、给个强度、可选"只由它照亮"或"屏蔽地图环境光"。代价见
[光源组件详解](#光源组件详解) 的 ②。

**4. 生成「游戏内可调」的 VRChat 参数** —— 点一下按钮，在 `Assets/NonToonLightAdjuster/` 下生成：

| 生成物 | 内容 |
|---|---|
| Animator Float 参数 | 默认名 **`NT_Light`** |
| 两条曲线剪辑 | `..._低.anim` / `..._高.anim`，曲线绑定 Renderer 的 `material.<你选的属性>` |
| 一层 Animator 层 + 1D BlendTree | 由 `NT_Light` 在两条剪辑之间混合（阈值 0 / 1） |
| VRC Expression Parameter | Float、默认 0、**占 8 bit 同步内存** |
| Expression Menu 径向控件 | 名字「光照强度」，类型 Radial Puppet → `NT_Light` |

**驱动哪个属性可选**：

| 选项 | 适用 |
|---|---|
| **`_LightMinLimit`（默认）** | 防煤主力：径向 = 亮度下限，0 = 官方默认（暗图会黑），1 = 很亮。零采样 |
| `_LightMaxLimit` | 压过曝 |
| `_SelfLightIntensity` | 用自有光那套时（需先打开自有光源） |

于是玩家戴上 avatar 后，**在 Action Menu 里拉一下径向就能自己调亮度**。

参数代价（官方文档）：`Float` 占 **8 bit**，VRChat 的**自定义同步参数上限 256 bit**；
不想给别人看就关掉「同步给别人看」（省 8 bit，但只有你自己看得到变化）。
`Radial Puppet` 给的是 **0.0–1.0**。

> 没装 VRCSDK 时，插件只生成 Animator 部分，并把「怎么手动建参数与菜单」逐条打出来。

**5. 上传前清理** —— 数出模型上本包的助手组件（① / ②）并一键移除。**移除不影响效果**
（那盏 `Light` 与材质里的烘焙结果都保留）。

#### 实测证据（工具 0.4.8）

| 检查 | 结果 |
|---|---|
| 全黑 + 下限 0（负向对照） | 非黑 **0.0%**、均值 0.0020 —— 确实是一块煤 |
| 全黑 + 下限 0.15 / 0.35 / 0.6 | 均值 0.0719 / 0.1066 / 0.1353，单调递增 ✓ |
| 全黑 + 自有光（兜底） | 均值 0.0020 → 0.1684（83 倍）✓ |
| 生成的 Animator / 剪辑 / BlendTree / 参数 / 菜单 | **29 项断言全过**：绑定 `material._LightMinLimit`、`classID 23`、曲线值 0.05/0.6、阈值 0/1、Float + saved、RadialPuppet |
| **未验证** | 曲线在**运行时**是否真的改材质：本机批处理下动画预览整体失效（连位置曲线都采样不动），**需要你上传一次到 VRChat 实测** |

## 功能总览

材质面板上的分组（打开任意 NonToon 材质即可看到）。

### 主色与基础

| 功能 | 说明 |
|---|---|
| 渲染模式 | 不透明 / 镂空（Cutout）/ 半透明 |
| 主贴图 + 共享遮罩 + 共享渐变 | 一张遮罩图给所有模块按通道取用 |
| 法线贴图 + 粗糙度 + 裁剪阈值 | 支持从法线贴图里取粗糙度 |
| 反照率遮罩（RGBA 四通道） | 一个模块控四个区域 |

### 阴影（1/2/3 层）

- **三层阴影色**，每层各有：颜色、边界（Border）、模糊（Blur）
- **逐像素阴影遮罩**：一张图的三个通道分别控制三层阴影的强度/边界/模糊
- **阴影主色强度**、**边界颜色与范围**、**AA 强度**
- lilToon 的这些项**可以从 lilToon 材质 1:1 转换过来**

### 光照调整

| 项 | 作用 |
|---|---|
| 光照上下限（Min/Max Limit） | 把受光强度压进一个范围，控制整体明暗对比 |
| 单色光照（Monochrome） | 去掉光的颜色，只用明暗（避免被地图灯光染色） |
| 无光照（As Unlit） | 完全不吃光，永远满亮 |
| 阴影方向偏置 | 修"侧光下渐变打架" |

### 其他模块

## 注意事项与性能

### 性能：默认全是最省的那档

**每像素自阴影采样**：

| 配置 | 采样 / 像素 |
|---|---|
| 自有光源关（**默认**） | **0** |
| 自有光源开、强度 0（只要光不要影） | **0** |
| 自有光源开、PCSS 关（硬阴影） | **1** |
| PCSS **低（默认）** | **20** |
| PCSS 中 / 高 / 极高 | 36 / 60 / 96 |
| 接收遮罩 / 阴影强度遮罩 | 各 +1（**默认 0 = 不采样**） |

采样**只在光源包围盒内 + 阴影距离之内**才发生。组件面板会直接把当前预算写在上面。

### 实时光源（① 与 ② 的实时光源模式）

- 额外渲染一张阴影贴图，**每个看到你的人都付这份开销**
- 占 VRChat 的 `Lights` 计数 → PC 上最高只能到 **Poor**
- Quest 端实时光基本不可用

### 其它

- **① 和 ② 不要同时开**：会双份打光。② 的实时光源模式会自动把材质里的自有光源关掉并警告
- **② 的阴影是静态的**：换姿势/换衣服后要重新烘焙
- **自备阴影贴图的约定**：灰度 = 离光源近平面的归一化距离；贴图要**非 sRGB、不压缩、Clamp、无 mip**
- **渲染队列**：`NonToon.scshader` 的两个 SubShader 都**没有**声明 `Queue` 标签（`NonToonFur` 有 `AlphaTest`），
  队列靠编辑器写入 → **脚本创建或复制出来的材质不会自动带队列**，半透明可能显示异常，手动物理一下 Queue 即可
- **面板仍有约 48 条英文**：`SrcBlendRGB` / `ZWrite` / `Ref` / `Comp` / `Pass` / `Cull` / `AlphaToMask` 等，
  这些是 ShaderCore 的底层属性，本包补不到

## 与 AAO 和 MA 等优化工具共存

VRChat 圈里很多人用 **AAO（Avatar Optimizer）** 和 **MA（Modular Avatar）**。下面是本包与它们的实际关系
（依据 AAO/MA 官方文档 + 本机实测；**没验证到的会明确写出来**）。

### AAO（Avatar Optimizer）

**能一起用，外观不会出问题。** 但有两件具体的事要知道：

**1) 网眼合并 + 「亮度径向」：兼容**

AAO 的 `Merge Skinned Mesh` 文档原文：

> "material-related animations **will work without modification**."

边界条件是（AAO changelog PR #769）：

> "Merge Skinned Mesh **does not support animating material properties differently**… 
> **If you animated all materials from same animations, your animation will not be warned.**"

本包 ③ 插件生成的剪辑，对**每个 Renderer 写的是同一条曲线、同一个值** —— 正落在"支持"的那一侧。
> ⚠️ 但如果你手动把它改成"每个材质不一样的值"，就会进入 AAO 明确不支持的情况（AAO 会警告，且可能失效）。

**2) 材质合并 / UV 打包：本包暂时拿不到（性能差异）**

AAO 的 `Merge Material` 与 `Trace and Optimize` 的贴图优化**只对提供了 Shader Information 的着色器生效**。
AAO 官方列出已支持的有 Standard / ToonLit / ToonStandard / **lilToon** —— **NonToon 不在其中**（我们还没注册这个 API）。

所以用 AAO 时：

| | lilToon | NonToon (Fork) |
|---|---|---|
| 纹理图集 / UV 打包 / 移除被关掉功能的贴图 | ✅ 支持 | ❌ 走"保守路径"，不做这些优化（**外观不受影响**，只是少一层优化） |

- 如果你**必须**依赖 AAO 的贴图图集，现阶段请在需要图集的部位用 lilToon
- 这条已列入我们的待办（注册 AAO 的 `ShaderInformation`，需要装了 AAO 的环境才能验证）
- 另外 AAO 的材质合并**本身就不支持视差（Parallax）与 UV 滚动**类功能，而本包有 MatCap VR 视差 —— 即使以后注册了 API，这部分也不适合走合并

**3) Trace and Optimize 会规整动画层**

AAO 会把 `Entry-Exit` 形状的层转成 BlendTree —— 我们生成的层本来就是 BlendTree，参数与曲线不变。
AAO 官方承诺 T&O "**never let it affect the appearance**"，所以判定风险低。
> ⚠️ **未验证**：我们生成的层/参数在 AAO 实际构建中会不会被判为"未使用"而优化掉（本机没装 AAO）。
> 如果你同时用 T&O 和径向，麻烦实测一次；若径向失效，请反馈。

### MA（Modular Avatar）

| 组件 | 与本包的关系 |
|---|---|
| **Remove Vertex Color** | ⚠️ **别和「从顶点色取描边宽度」一起用**：本包的描边在开启该选项时用 `vertex.color.rgb * 2 - 1` 当法线（`sc_common.hlsl`），顶点色被移除后描边方向会走形。该选项**默认关闭**，没开就没影响 |
| **Merge Animator** | ⚠️ 它的路径默认"**相对于 Merge Animator 组件**"，所以**不要用它来装本包 ③ 生成的 FX 控制器**（我们写死的 `material._LightMinLimit` 绑定会指向错对象）。③ 生成的控制器是**直接写进 avatar descriptor 的 FX 层**的，这是正确用法 |
| **Material Swap / Material Setter** | 可以用。运行时亮度径向仍会写"当前材质"的属性 ⇒ 行为一致；但**换上的材质不会保留它自己面板里的亮度值**（会被径向覆盖） |
| **Menu Item / Parameters** | ③ 生成的 Expression Parameter 与菜单控件是标准资产，和 MA 的菜单系统可以共存（注意别重复添加同名参数） |

### Quest 相关

| | 结论 |
|---|---|
| **NonToon / NonToonFur** 采样器 | 去重后只有 **7 个**（GLES3 规范保证 ≥16）✅ 采样器不是瓶颈 |
| **NonToonFur（毛发）** | ❌ **有 7 个几何着色器 pass**，而 GLES3 不支持几何着色器 ⇒ **Fur 请只在 PC 上用**（这也与上游那台"Fur 在老 N 卡/Radeon 上膨胀"的 issue 同源） |
| **本体的 `#pragma target 5.0`** | ⚠️ **未验证**：12 个 pass 用 target 5.0（这个值是**继承自官方 0.1.3**，不是本分支引入）。Unity 里它要求 DX11 / ES3.1+AEP / Vulkan；Quest 的 GLES3 路径是否存在编译风险，本机**没有 Android 构建支持、无法实测**。对照：lilToon 主要用 target 3.5，明显更保守。**如果你在 Quest 上遇到粉色/异常，请带上机型反馈** |

## 常见问题

**Q：装上去会不会和官方 NonToon 并存？**
不会。包 id 相同，所以是**升级**官方版（见上一节）。

**Q：升级到 0.3.7 后，场景里某个组件变成 `Missing (Mono Script)`？**
0.3.6 及更早的包里，「① Avatar 光源」这个脚本文件**漏带了 `.meta`**，于是 Unity 给每台机器生成的是
不同的 GUID —— 你挂好组件之后换机器打开、或重装这个包，引用就会断。0.3.7 已修。
**处理**：把 Missing 的组件删掉，重新挂一次并重填参数。从 0.3.7 起 GUID 已固定，以后升级不会再断。

**Q：上传时 SDK 说我有「不允许的组件」？**
本包的 ① / ② 是**编辑器期的设置载体**，VRChat 里不会运行（官方白名单不允许自定义脚本）。
它们的效果已经落到「那盏 Light」和「材质里烘焙好的参数/贴图」上，**移除组件不影响效果**。
③ 插件面板里有「上传前清理」按钮可以一键移除。

**Q：我明明选了简体中文，为什么面板里还有英文？**
0.3.7 起不需要你手动选。剩下约 48 条是 ShaderCore 自己的底层属性（见「注意事项」），本包补不到。

**Q：转换后看着不太一样？**
转换是近似的（MatCap、边缘光、距离淡出、毛发、描边尤甚）。请看转换报告里标了「近似」的条目，
或参考工具包里的 `Mapping.md`。

**Q：Quest 上能用吗？**
着色器侧功能可以；**实时光源**（① 、② 的实时光源模式）基本不可用。**② 的烘焙自阴影可用**，
③ 生成的 Animator 参数也是 Quest 可用的（都是白名单内的东西）。

**Q：老是提示 ShaderCore 模块缺失？**
装完本包会在编辑器加载时自动补注册并重导着色器（ShaderCore 的模块表只扫描一次，升级上来会静默丢模块）。
控制台看到 `[NonToon] …补注册模块` 就是它在干活。

**Q：地图里的光很难看，我不想每次都去调材质？**
用 ③ 插件：点「防煤（下限 0.35）」写入材质，再生成径向参数，游戏里随手调。
或者用 ② 的「匹配世界光颜色 / 方向」，或者干脆勾「只由它照亮」与地图光完全解耦。

**Q：从很老的版本升上来，菜单里出现两个转换器？**
见「从不同版本升上来」：把 `Packages/jp.lilxyzw.nontoon` 整个删掉重装一次。

## 已知限制

- **只在 BiRP（VRChat）上保证可用**；URP 分支在 Unity 2022.3 上是死代码
- **VRChat 内做不到实时自阴影**：avatar 不能带相机/渲染纹理，自阴影只能是"烘焙那一刻的姿态"
- 转换是近似的，以下**未移植**：贴花（Decal）、溶解（Dissolve）、闪烁、荧光、宝石（Gem）、
  折射、AudioLink、UV 动画、视差深度、`_Emission2nd*`、渐变发光 —— 转换器会自动警告并跳过
- `NonToon.scshader` 没声明 `Queue` 标签（见「注意事项」）
- 官方 issue #7（Fur 在 Radeon / 老 N 卡上异常膨胀）**未处理**；上游作者说只能缓解、不能根治
- 面板里仍有约 48 条英文（ShaderCore 的底层属性）
- **实时光源与 VRChat 性能等级冲突**：PC 上最高只能到 Poor（这是 VRChat 的规则，不是本包的缺陷）
- ③ 生成的材质属性曲线**运行时行为未在本机验证**（批处理下动画预览失效），需要你上传一次实测
